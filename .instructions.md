# Development Instructions for AI Agents - EcoCycle Webapp

> Guidelines for AI-assisted frontend development on the EcoCycle React webapp.

## 🎯 Project Overview

- **Purpose**: React SPA for circular economy platform UI
- **Type**: Single Page Application
- **Tech Stack**: React 17, Redux, Redux-Saga, Material-UI, TypeScript 4.5+
- **Build**: Create React App with Webpack

---

## 🏗 Architecture Pattern

**Redux-First State Management**:
- All async operations go through Redux-Saga
- Components dispatch actions, never call APIs directly
- Selectors retrieve computed state slices
- Material-UI provides consistent styling

### Key Redux Slices
```
auth         - Current user, authentication state
groups       - Group data and CRUD operations
products     - Product catalog
places       - Locations and addresses
vehicles     - Vehicle fleet
offers       - Buy/sell listings
```

### API Service Layer
```
src/services/
├── api.ts                 # Base Axios instance + interceptors
├── productService.ts      # Product CRUD endpoints
├── placeService.ts        # Place/location endpoints
├── vehicleService.ts      # Vehicle endpoints
└── ...
```

---

## 📂 File Naming & Conventions

**Components**: PascalCase with `.tsx`
- `ProductForm.tsx`, `PlaceList.tsx`, `ValueFieldset.tsx`

**Redux Slices**: camelCase with `.slice.ts` suffix
- `products.slice.ts`, `groups.slice.ts`, `auth.slice.ts`

**Sagas**: camelCase with `.saga.ts` suffix
- `productsSaga.ts`, `placesSaga.ts`

**Selectors**: `selectXxx` pattern
- `selectProducts`, `selectCurrentUser`, `selectGroupPlaces`

**Services**: camelCase with `Service` suffix
- `productService.ts`, `authService.ts`

## ✅ DO's

1. **DO** dispatch Redux actions from component event handlers
2. **DO** use Redux-Saga for all API calls and side effects
3. **DO** create reusable fieldsets for form sections
4. **DO** use MUI components for consistency
5. **DO** validate forms with Formik + Yup before submission

---

## ❌ DON'Ts

1. **DON'T** call APIs directly from components (use Redux + services)
2. **DON'T** manage async state locally (use Redux slices)
3. **DON'T** mutate Redux state (use immutable patterns)
4. **DON'T** hardcode API URLs (use environment variables)
5. **DON'T** create deeply nested component hierarchies (keep < 5 levels)

---

## 📋 Common Workflows

**Adding a new page with CRUD**:
1. Create Redux slice: `featureName.slice.ts` with actions
2. Create saga: `featureNameSaga.ts` for API calls
3. Create page component: `pages/feature/FeaturePage.tsx`
4. Create form component: `components/FeatureForm.tsx`
5. Wire up to Router in App.tsx
6. Add navigation menu entry

**Creating a reusable fieldset**:
1. Extract form section logic into component
2. Accept props for field names, initial values
3. Wrap sub-inputs with Formik context
4. Use MUI Form components
5. Export and reuse in multiple forms

**Handling authentication state**:
1. Store JWT token in Redux `auth` slice
2. Add interceptor to Axios for Authorization header
3. Create `PrivateRoute` wrapper for protected pages
4. Handle token expiration in saga with refresh
